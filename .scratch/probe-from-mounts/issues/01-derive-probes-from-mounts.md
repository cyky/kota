# 01 — Derive the containment probes from the Sandbox's mounts

Status: ready-for-agent
Category: refactor

## Parent

Architecture review 2026-10-18, candidate 2. Builds on `.scratch/agent-module/`.

## What to build

Today `prepareSession` builds two lists side by side: the mounts in `sandbox.Inputs` and the probe targets in `check.Mounts` (`cmd/kota/main.go:847-857`). Each read-only mount is added twice, and one left out of the second list is mounted but never probed. The shared Go module and corepack caches are already in that state: `sandbox.Build` mounts them read-only in every run Session (`internal/sandbox/spec.go:365-369`), and no probe checks them.

- `sandbox.Build` returns, with the compose spec, the probe expectations derived from the agent service's own volumes: `Expect{ReadOnly, Pinned, Masked, State}`. Every read-only volume is in `ReadOnly`, every pinned bind in `Pinned`, every mask in `Masked`, and the state volume's target in `State`.
- `sandbox.Mount` gains `Mask bool`. `mask.Layout.Bind` sets it; `Layout.Targets()` is deleted.
- `check.Run` takes `sandbox.Expect`; `check.Mounts` is deleted, and so are main.go's appends to `sess.mounts`.
- The rest of `prepareSession` (its prep/run branches and cleanup exits) stays as it is.

Behaviour change: run Sessions now also probe the read-only shared caches (`GoModCache`, `CorepackHome`) and anything else `Build` mounts read-only. A cache mounted writable by mistake would refuse the Session.

## Acceptance criteria

- [ ] `sandbox.Build` returns `Expect` derived from the volumes it emits
- [ ] A `sandbox` test checks, across modes and inputs (deps, engine, state, masks, pinned, `--ro`), that every read-only, pinned and masked volume of the agent service is in `Expect`, and nothing else is
- [ ] `check.Mounts`, `mask.Layout.Targets` and main.go's probe-list appends are gone
- [ ] The agent-module test "every `Prepared.ReadOnly` target is probed" and the hand-written "probes don't check %s is read-only" assertions are deleted, now covered by the `sandbox` test
- [ ] `kota check` lists the shared caches among the read-only probes
- [ ] `go test ./...` passes, and the Docker integration tests pass
- [ ] `docs/protections.md` mentions that the shared caches are probed read-only
