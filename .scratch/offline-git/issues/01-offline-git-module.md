## What to build

Running git safely in an offline container is spread over `approval`, `changereport`, `nohistory` and main.go: three runner types (`approval.Runner`, `changereport.Runner`, `nohistory.WritableRunner`), two production adapters that repeat the same path-policy loop (`offlineRunner`, `writableRunner`, `cmd/kota/main.go:2166-2196`), the hardening flags in two forms (`changereport.gitPrefix`, `nohistory.gitFunc`), repository discovery in three places (`approval.FindRepo`, `nohistory.commonDir`, `changereport.ReadRefs`' own `.git` check) and `pointer()` copied in `approval.go` and `nohistory/return.go`. `nohistory` imports `approval` for its git helpers.

A new package `internal/offlinegit`:

- `type Runner func(Job) (string, error)`, with `Job{ReadOnly []string; Writable string; Dir string; Cmd []string}`; `Writable` empty means none. It replaces all three runner types.
- The production adapter: `docker.RunOffline` / `RunOfflineWritable` in the base image, checking every mount (the writable one too) against the `--ro` path policy once. main.go only builds it with the image, UID/GID and policy.
- `Git(run, job, args...)` runs one hardened git command; `Script(run, job, body)` runs a script with the hardened `g()` function in front. The hardening flags (`safe.directory=*`, `core.fsmonitor=false`, `--no-optional-locks`) are private.
- `FindRepo(project) (Repo, bool, error)`: discovery without running git, as `approval.FindRepo` does today, with the mounts it needs and whether `.git` is a directory or a linked `.git` file (worktree or submodule). `ReadRefs` keeps refusing linked repositories, using this instead of its own `Lstat`.
- `ReadStatus` moves here from `approval`. `approval` keeps `NeedsConfirmation` and the prompt; `nohistory` no longer imports `approval` (move `ReadLine` to wherever its use fits).

Out of scope: the git calls kota still runs on the host (issue 02).

Tests: `approval`, `changereport` and `nohistory` tests use a fake `Runner` or a local runner that executes git directly in a temp repo. Only the adapter's tests and the existing integration tests use Docker.

Deviations from the plan:

- `Script(run, job, body, args...)` takes positional args: the clone, export and import scripts need them.
- `Repo` also has `Top` and `CommonDir`, so `nohistory`'s `commonDir` and its "at the repository's top" `Lstat` go too. Discovery now exists only in `offlinegit.FindRepo`.
- `ReadLine` moved to `interrupt`, next to `Ask`, which runs every prompt that reads it.
- Extra config goes to `g` (`g -c core.hooksPath=/dev/null ...`). The import script wraps it as `o()` with `--git-dir`. The clone gains `--no-optional-locks`, and only `git clone` gets `protocol.file.allow=always`.
- `ReadRefs` now returns an error, shown as the existing "could not record git refs" warning, when `.git` is a symlink or an unreadable `.git` file. Before, it silently skipped the commit check.
- The full-auto status integration tests moved from `approval` to `offlinegit` and use the production adapter with a test policy.
