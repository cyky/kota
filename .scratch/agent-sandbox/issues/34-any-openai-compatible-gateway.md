# 34 — Support any OpenAI-compatible Gateway, such as LiteLLM

Status: needs-triage
Category: enhancement

## Parent

`.scratch/agent-sandbox/PRD.md`

## What to build

kota already works with any **Gateway** that speaks the OpenAI API. It uses only `GET /v1/models` (the model list and the gateway probe), `/v1/chat/completions` (through the agents) and an optional `Authorization: Bearer` key. A LiteLLM proxy serves all three, so `KOTA_GATEWAY=http://host.docker.internal:4000` works today. Its `model_name` aliases become kota's model IDs, so `assets/models.yaml` must use the same names.

What's missing is that the docs and messages assume llama-swap. More importantly, nothing warns that a **Gateway** which forwards to a cloud provider gives the agent a route out. The **Gateway** is the one hole in the **Sandbox**, and the probes trust whatever answers there. A LiteLLM config with one OpenAI or Anthropic entry lets the agent send project code to the internet, which breaks threat-model item (1) in `docs/sandbox.md`, and kota can't see it.

Possible scope:
- Docs and messages: say "OpenAI-compatible gateway" where kota means any **Gateway**, and keep llama-swap as the default and the documented setup. This includes the README intro and requirements, the `--gateway` and key help text, and the model-swap warning in `cmd/kota/main.go`, which names llama-swap.
- `docs/sandbox.md`: a **Gateway** that forwards to remote providers is a route out. Point kota only at a local-only instance, and keep any cloud routing on a separate instance.
- Note that LiteLLM routes but doesn't load or unload models, unlike llama-swap's on-demand swapping and groups. That matters on a single machine.
- Maybe: a warning when the gateway's model list contains names that look remote. This can only be a heuristic: kota can't verify where a gateway forwards, so it's never a guarantee.
