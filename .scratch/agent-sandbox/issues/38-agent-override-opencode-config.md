## What to build

An **Agent override** for opencode's `opencode.json`, on the mechanism from issue 35. A user who puts an `opencode.json` in `$XDG_CONFIG_HOME/kota/opencode/` gets its allowed settings in every opencode **Session**, layered between the bundled base and kota's own keys: bundled base, then the override's allowed keys, then what `opencode.Render` sets (provider, models, enabled providers, and the `--auto` permissions).

`opencode.json` is mostly gateway wiring and code loading, and opencode v2 moved its UI settings to `tui.json`, so the allowlist is small:
- Allowed: `compaction`. `$schema` as in issue 35.
- Refused with a pointer to `tui.json`: `keybinds`, `theme`.
- Refused, with the reason in the error: `plugin`, `mcp`, `lsp`, `formatter`, `command`, `agent`, `shell` (run code); `instructions`, `watcher` (read paths); `provider`, `model`, `small_model`, `enabled_providers`, `disabled_providers`, `permission`, `tools` (gateway wiring and the approval model, which `--auto` controls); `share`, `autoupdate`, `server`, `experimental`; anything else not allowed.

Refusals and the startup line work as in issue 35. Check the key names against the pinned opencode version's config schema when implementing.

Docs: add `opencode/opencode.json` to the usage text and docs, saying that keybinds and theme belong in `tui.json`.

## Acceptance criteria

- [ ] `compaction` in the override takes effect in an opencode **Session**
- [ ] The bundled base's `share: disabled`, `autoupdate: false` and permissions survive any override, and `--auto` still works
- [ ] `keybinds` or `theme` in the override refuses the **Session** with an error pointing to `tui.json`
- [ ] Another refused key (for example `mcp`) refuses the **Session** with an error naming the file and key, and why
- [ ] The startup line lists the file
- [ ] Usage text and docs describe it
- [ ] Tests use a fake HOME / XDG_CONFIG_HOME
