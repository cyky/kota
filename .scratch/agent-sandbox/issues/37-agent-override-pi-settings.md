## What to build

An **Agent override** for pi's `settings.json`, on the mechanism from issue 35. A user who puts a `settings.json` in `$XDG_CONFIG_HOME/kota/pi/` gets its allowed settings in every pi **Session**, layered between the bundled base and kota's own keys: bundled base, then the override's allowed keys, then the keys kota sets (`defaultProvider`, `defaultModel`).

Allowed (pi 1.2.0 names; a group allows everything under it):
- Thinking: `defaultThinkingLevel`, `modelThinkingLevels`, `thinkingBudgets`, `hideThinkingBlock`
- Interaction: `steeringMode`, `followUpMode`, `doubleEscapeAction`, `treeFilterMode`
- Context: `compaction`, `branchSummary`, `retry`
- Terminal and display: `theme`, `quietStartup`, `tuiMode`, `fullscreenExitOutput`, `fullscreenScrollbar`, `fullscreenCopyOnSelect`, `fullscreenWheelScrollLines`, `editorPaddingX`, `outputPad`, `autocompleteMaxVisible`, `showHardwareCursor`, `terminal`, `images`, `markdown`

Refused, with the reason in the error:
- Loads files or code: `packages`, `extensions`, `skills`, `prompts`, `themes` (so `theme` can only name a built-in theme)
- Runs commands: `shellPath`, `shellCommandPrefix`, `npmCommand`, `externalEditor`
- Containment, telemetry, network: `defaultProjectTrust`, `enableInstallTelemetry`, `enableAnalytics`, `httpProxy`, `transport`
- Gateway wiring and session state kota owns: `defaultProvider`, `defaultModel`, `enabledModels`, `defaultTools`, `sessionDir`
- Anything else not on the allowed list

Refusals, `$schema` handling and the startup line work as in issue 35. Check the allowlist against the pinned pi version's `docs/settings.md` when implementing; if a key was renamed, keep the intent and note the change on this issue.

Docs: add `pi/settings.json` and its allowed keys to the usage text and docs.

## Acceptance criteria

- [ ] An allowed setting (for example `theme` or `defaultThinkingLevel`) in the override takes effect in a pi **Session**
- [ ] The bundled base's `defaultProjectTrust: never`, disabled telemetry and disabled llama.cpp extension survive any override
- [ ] kota's `defaultProvider` and `defaultModel` win over the override
- [ ] A refused key (for example `extensions`) refuses the **Session** with an error naming the file and key, and why
- [ ] Nested groups merge key by key (setting `terminal.showImages` keeps other `terminal` defaults from the base)
- [ ] The startup line lists the file
- [ ] Usage text and docs describe it
- [ ] Tests use a fake HOME / XDG_CONFIG_HOME
