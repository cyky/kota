## What to build

Small output problems found in the issue 17 trial run, done together:

1. **Probe columns.** In `check` and `run`, probe names longer than the name column push the "must fail" column out of line. Examples: `internet [2606:4700:4700::1111]:443`, `read-only /workspace/.kotaignore`, `read-only /etc/kota/opencode.json`. Size the column to the longest name.
2. **Docker Compose progress.** `prep` and `run` print a garbled progress line every time (`[+]  1/1t 1/11`, `[+]  1/1te 1/1`), as if two updates overwrite each other. Find the cause, or switch these `docker compose` calls to plain or quiet progress output.
3. **Prep failure buried.** When the install fails, `kota: prep install failed: exit status 1` comes after npm's full error and usage text (around 150 lines for an out-of-date lock file). Put a short summary after the install output: which command failed, and the first error line if it can be found.

## Agent Brief

**Category:** bug
**Summary:** Fix three output problems: misaligned probe table, garbled Docker Compose progress, and a prep failure buried under the install output

**Current behavior:**
- The probe table printed by `check` and `run` (one row per `probe.Result`: status, name, "must fail"/"must succeed", outcome) pads the name to a fixed width. Several current probe names are longer than that, which pushes the remaining columns out of line.
- `prep` and `run` print a garbled Docker Compose progress line every time, e.g. `[+]  1/1t 1/11`. The likely source is `docker compose run` attached to the terminal, which draws its TTY progress display for dependency services while other output is written. Confirm this first.
- When the install step of `prep` fails, the only kota line, `kota: prep install failed: exit status 1`, appears after the package manager's full output, which can run to about 150 lines.

**Desired behavior:**
- The name column is as wide as the longest probe name in the table being printed, so every row lines up.
- No Compose progress display is drawn by kota's `docker compose` calls. Compose's global `--progress` option (`quiet` or `plain`) is the expected fix. Container output and the interactive agent session must be unaffected.
- A failed prep install ends with a short summary after the install output: which command failed (the install step from the dependency plan), its exit status, and the first error line from the output when one can be found (for example, an `npm ERR!` or `npm error` line). Without a recognisable error line, the summary still names the command. The install output itself still streams to the terminal as it does now.

**Key interfaces:**
- The function that prints `probe.Result` rows for `check` and `run`
- The `docker.Session` methods that run `docker compose` (`up`, `run` and the interactive agent run)
- The prep install step and the `deps.Plan` steps it runs

**Acceptance criteria:**
- [ ] Probe rows line up for all current probe names, including `internet [2606:4700:4700::1111]:443` and `read-only /etc/kota/opencode.json`
- [ ] `prep` and `run` print no Compose progress lines
- [ ] A failed prep install ends with a summary naming the failed command, and the first error line when one is found
- [ ] Unit tests for probe table alignment and for picking the first error line; existing tests updated

**Out of scope:**
- Changing which probes run or what they check
- Hiding or truncating the install output itself
- Other output changes not listed here
