# 36 — Agent override for pi's keybindings.json

## What to build

An **Agent override** for pi's keybindings, on the mechanism from issue 35. A user who puts a `keybindings.json` in `$XDG_CONFIG_HOME/kota/pi/` (default `~/.config/kota/pi/keybindings.json`) gets those bindings in every pi **Session**.

pi 1.2.0 reads keybindings from `<agent-dir>/keybindings.json`: a map of action ids (such as `app.session.new`) to a key or a list of keys, where an empty list disables the action. Each configured action replaces its default.

Behaviour:
- The whole file is allowed: it only maps keys to named actions, nothing in it loads or runs anything. `$schema` is dropped before merging, as in issue 35.
- The rendered `keybindings.json` is written into pi's agent dir read-only, like `settings.json`. Without an override, pi gets no `keybindings.json` (or an empty one) and uses its defaults.
- Invalid JSON, a path that isn't a regular file, a file over the size cap, or a value that isn't a string or list of strings refuses the **Session**, with the same error shape as issue 35.
- The `kota run` startup line lists this file when present.

Docs: add `pi/keybindings.json` to the usage text and docs next to the opencode override.

## Acceptance criteria
