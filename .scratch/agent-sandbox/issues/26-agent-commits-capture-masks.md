# 26 — Agent commits capture mask placeholders

Status: ready-for-agent
Category: bug

## Parent

`.scratch/agent-sandbox/PRD.md`

## What to build

Found in the issue 17 trial run. pi, in full auto, committed its README edit with `git add -A`. The commit also contained:

- the empty files mounted over paths that don't exist on the host (`.envrc`, `.kotaignore`, `kota.Dockerfile`, `kota.yaml`), added as new empty files;
- the masked `.env` (untracked on the host, not in `.gitignore`), added as an empty file;
- the masked, tracked `.npmrc`, recorded as emptied;
- `.claude/settings.local.json`, which the host ignores only through the global excludes file `~/.config/git/ignore`. The sandbox doesn't have that file.

No secret leaked, but pushing the commit would delete or empty files in the repo, and add junk files to it. The change report only looks at files in the working tree, so it said nothing about the commit.

Two parts, to decide in triage:

1. **Keep the placeholders and masks out of commits made in the sandbox.** Options:
   - Point `core.excludesFile` (through the `GIT_CONFIG_*` variables in `gitEnv`) at a generated file. It would list the placeholder and masked paths and include the host's global excludes. This only covers untracked paths, so the tracked `.npmrc` would still be recorded as emptied.
   - Check new commits after the session for placeholder or masked paths and warn about them.
2. **Report new commits in the change report.** Record `HEAD` at session start. On exit, list the commits made in the session, and flag any that touch placeholder, masked or watched paths.

## Acceptance criteria

- [ ] After a session in which the agent runs `git add -A && git commit`, either the commit contains no placeholder or masked paths, or kota warns that it does
- [ ] The change report lists the commits made during the session
- [ ] Files ignored by the host's global excludes behave the same inside the sandbox, or the README says they don't
- [ ] Integration test for an agent commit made with `git add -A`

### 2026-10-16 (grilling)

> *This was generated by AI during a grilling session.*

Decisions, folded into the Agent Brief below:

1. **Warning, not failure.** The warning goes in the **Change report** with a restore hint (paths and a `git restore --source` command). kota's exit status stays the agent's. Nothing is amended or reverted.
2. **No host data in the Sandbox.** The earlier plan copied the host's global excludes file into the Sandbox. That was dropped: resolving `core.excludesFile` with project scope would let an agent-written `.git/config` point it at any host file, and even the global file reveals path names. The Sandbox excludes file holds only placeholder and untracked masked paths, which the agent already sees. The host's global excludes are checked after the command, outside the Sandbox, and commits that add a globally ignored path get a warning.
3. **Watched paths in commits** are warned about only when the working-tree report didn't already flag them (a change committed and then undone in the working tree).
4. **Commands:** `run`, `shell` and `prep`, the same as the working-tree report. A dependency install script can commit too.
5. **History rewrites** (reset, rebase, amend, branch switch) are reported, with the old commit named for recovery, and the new commits are still listed and checked.
6. **All local branches and tags** are covered, not only the current `HEAD`.

git never runs on the host against the project's repository, for reading refs or commits either: `approval.ReadStatus` already explains why (agent-written config and `.gitattributes` can run filters, textconv and fsmonitor).

## Agent Brief

**Category:** bug
**Summary:** Keep mask placeholders and untracked masked files out of commits made in the sandbox, and add the branches, tags and commits a command created or changed to the **Change report**, with warnings for commits that touch placeholder, masked or globally ignored paths, or hide changes to watched paths.

**Current behavior:**
- Inside the sandbox, git gets only the settings passed through `GIT_CONFIG_*` (`safe.directory` and the host identity). It has no global excludes file, so files the host ignores only through `~/.config/git/ignore` (or a host `core.excludesFile`) show up as untracked.
- The `mask.Layout` mounts empty files over missing protected paths (`Mount.Placeholder`) and over masked paths (`Mount.Mask`). `git add -A` stages them: placeholders and untracked masks become new empty files, and a tracked masked file is recorded as emptied.
- The change report on exit only compares watched files in the working tree. It says nothing about commits made during the session.

**Desired behavior:**

Applies to every command that runs project code in a container: `run`, `shell` and `prep`, the same places the working-tree report runs today. In a project that isn't a git repository, none of this applies.

1. **Excludes file.** Each command gets a generated excludes file, mounted read-only and set as `core.excludesFile` through the `GIT_CONFIG_*` variables. It holds one anchored entry per placeholder path and per untracked masked path in the project (not paths inside `.git`), made relative to the repository root when the project is a subdirectory of a larger repository. `git add -A` then doesn't stage placeholders or untracked masks. Nothing from the host goes into it: in particular not the host's global excludes file (see 3).
2. **Commit check.** Before the command, record the tips of all local branches and tags and the `HEAD` commit (`git for-each-ref refs/heads refs/tags` and `git rev-parse HEAD`, or "unborn"). After it, read them again and check the commits in `git rev-list <new tips and HEAD> --not <old tips and HEAD>`: every commit reachable now that wasn't before, on any branch, a detached `HEAD` included. git never runs on the host against the project's repository, for either reading: run it the way `approval.ReadStatus` does, through its `Runner` (offline container, read-only mounts, `core.fsmonitor=false`, `--no-optional-locks`). Commands that show diffs must not run textconv or external diff drivers (`--no-textconv --no-ext-diff`, or plain `diff-tree --name-status`).
3. **Globally ignored paths.** The host's global excludes file is found without reading anything in the project: `git config --global --get core.excludesFile` run on the host outside the project (never `-C <project>`, repository config never consulted), otherwise `$XDG_CONFIG_HOME/git/ignore` or `~/.config/git/ignore`. It must be a regular file (a symlink to one is fine) under a size cap (1 MiB). It is mounted read-only into the check container only, never into the Sandbox. A commit that adds a path it ignores gets a warning.
4. **Report.** After the existing working-tree warnings, the **Change report** shows, in order:
   - branch and tag changes: new, moved, deleted;
   - when `HEAD`'s old commit is no longer reachable from the new `HEAD` (reset, rebase, amend, branch switch): a line saying so, naming the old commit and how to get it back (`git reset --hard <old>`, or `git reflog`);
   - the new commits (short hash and subject, control characters stripped), at most 20, then "... and N more";
   - warnings, never capped, one line per path naming the commits that touch it (`.npmrc  emptied in a1b2c3, d4e5f6`), for:
     - placeholder paths and masked paths added, emptied, modified or deleted;
     - paths the host's global excludes ignore, added;
     - watched paths changed in a commit but **not** flagged by the working-tree report, because the working tree no longer shows the change ("runs when the commit is pushed or checked out"). Watched paths the working-tree report already flagged aren't repeated.
   - a restore hint for placeholder and masked paths: the paths and `git restore --source=<parent of first bad commit> -- <paths>`. Not an amend command: the bad commit may not be the latest.

   Nothing changed prints nothing. The warnings never change kota's exit status, which stays the agent's (or the command's), and kota never amends, reverts or blocks a commit.

**Key interfaces:**
- `gitEnv` (builds the `GIT_CONFIG_*` env for the sandbox): gains `core.excludesFile`
- `mask.Layout` / `mask.Mount` (`Placeholder`, `Mask`): the source of the paths to exclude and check
- `approval.Runner` / `FindRepo`: the offline container and mounts for reading refs and commits
- `reportChanges` in `cmd/kota/main.go` and the `changereport` package: gain the ref changes, commit list and warnings, and need the working-tree result to leave out watched paths it already flagged

**Acceptance criteria:**
- [ ] After a session in which the agent runs `git add -A && git commit`, the commit contains no placeholder paths and no untracked masked paths
- [ ] A commit that records a tracked masked file as emptied produces a warning naming the file, with the restore hint
- [ ] A commit that adds a file ignored only by the host's global excludes file produces a warning; the global excludes file is not readable inside the Sandbox
- [ ] A watched file changed in a commit and then restored in the working tree produces a commit warning; a watched file changed and committed normally is reported once, by the working-tree report
- [ ] Commits on a branch created and left behind during the session are listed and checked, as are commits on a detached `HEAD`
- [ ] After a reset or amend of a commit that existed before the session, the report names the old commit and still checks the new ones
- [ ] The same report follows `prep`
- [ ] No git process runs on the host with the project's repository as its repository
- [ ] Integration test (fake `HOME`, never the real one): a project with a tracked masked file, an untracked masked file, a missing `.envrc` and a file ignored by the fake `HOME`'s global excludes; the agent runs `git add -A && git commit`; the assertions above hold
- [ ] README updated: the Sandbox excludes file, that host global excludes don't apply inside the Sandbox (kota warns about commits instead), and the branch, commit and warning parts of the **Change report**

**Out of scope:**
- Rewriting, reverting or blocking the agent's commits
- Remote-tracking refs, stashes and other refs outside `refs/heads` and `refs/tags`
- `--no-history` sessions (issue 29)
