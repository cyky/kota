## What to build

Found in the issue 17 trial run. An agent session renamed the package in `package.json` and added `"wrangler": "^4.0.0"` to devDependencies, without updating `package-lock.json`. The change report on exit only said `modified package.json`. The next `kota prep` failed in `npm ci` because the lock file was out of date. The new dependency, which would have run code on the next install, was only found with `git diff`.

For a modified watched file, show what changed, or at least where to look:

- For manifests that prep understands (`package.json`, `go.mod`, ...), list dependency, script and lifecycle hook changes, as the prep gate already does.
- For other watched files, print a short diff, or the `git diff -- <path>` command to see it.

## Agent Brief

**Category:** enhancement
**Summary:** For modified manifests, the change report names the dependencies and scripts that changed. For other modified watched files, it prints the command to see the diff.

**Current behavior:**
When a session ends, the change report compares snapshots of the watched files (`changereport.Files`, digests only) and prints one line per `changereport.Change`, e.g. `modified  package.json`. Nothing says what changed inside the file. A new dependency, or a new lifecycle script that runs on the next install, can only be found with `git diff`.

**Desired behavior:**
- For a modified `package.json` (at any depth): list each added, removed or changed entry in `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies` and `scripts`, with its old and new value. Lifecycle hooks that the install runs (`preinstall`, `install`, `postinstall`, `prepare`, and so on) are marked as such.
- For a modified `go.mod`: list each added, removed or changed `require` and `replace` entry.
- For every other modified or added watched file: print `git -C <project> diff -- <path>`, or `git -C <project> status -- <path>` for untracked files, so the user can look at it.
- To compare manifests, their content is kept when the session starts. They are read on the host before the agent runs. Digests alone are not enough.
- If a manifest can't be parsed before or after, fall back to the diff command, with a note that it could not be read. Never fail the report.
- Printed names and values come from agent-written files, so control characters are stripped or escaped before they reach the terminal.
- Applies wherever the session-end change report is printed (`run` and `shell`).

**Key interfaces:**
- `changereport.Files` / snapshotting: must also keep the content of manifest files at session start
- `changereport.Change` and the session-end report: gain per-change detail lines
- The package.json parsing already used for the dependency plan (`deps`) can be reused or extended

**Acceptance criteria:**
- [x] A dependency added to `devDependencies` in `package.json` during a session is named, with its version, in the change report
- [x] An added or changed `postinstall` script is named and marked as an install hook
- [x] A changed `require` version in `go.mod` is named with its old and new version
- [x] A modified watched file that isn't a manifest (e.g. `.envrc`) shows a `git diff -- <path>` command
- [x] An unparseable manifest falls back to the diff command without an error
- [x] Control characters in dependency names or script values are not written raw to the terminal
- [x] Unit tests cover the manifest comparison, and an integration or command-level test covers the report output

**Out of scope:**
- Lockfile diffs (`package-lock.json`, `go.sum`, ...): they keep the diff command
- Showing details in the prep gate's prompt (a possible follow-up)
- Fixing the out-of-date lockfile itself
- Changing which files are watched
