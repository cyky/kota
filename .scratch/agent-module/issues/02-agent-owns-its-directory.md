## What to build

Two phases on the agent module, replacing the per-agent wiring in `prepareSession` (`cmd/kota/main.go:768-828`, `860-874`) and `configure` (`main.go:2122-2134`):

```go
func (a *Agent) Prepare(dir string, note Note) (*Prepared, error)

type Note struct { Style instructions.Style; Engine string }

type Prepared struct {
    ReadOnly []sandbox.Mount
    Scratch  []string
    Env      map[string]string
    Command  []string
}
func (p *Prepared) Configure(c models.Catalog, auto bool, keyEnv string) error
```

- `Prepare` owns `dir` (`sessionDir/agent`): it creates the config files empty (mount sources must exist before compose starts), writes the note with `instructions.Note(note.Style, <its facts>, note.Engine)`, and copies its bundled extensions (`writeExtensions`, `main.go:527`, moves in). It returns every read-only mount, the scratch dirs (including the note's), the env (including opencode's inline cli.json, today's `overrideEnv`) and the default command.
- `Configure` renders each config with the catalog, `auto` and `keyEnv`, and writes it to the file `Prepare` created. The gateway URL comes from `sandbox.AgentGatewayURL()` inside the module.
- main.go keeps the `--no-history` state suffix, the shell command, `kota run -- cmd`, and appending `Prepared.ReadOnly` targets to `sess.mounts.ReadOnly` for the probes.
- `session.cfgFiles`, `notePath`, `noteScratch`, `extensions`, `overrideEnv` and `render` disappear from main.go, along with any bridge left by issue 01.

Tests:
- Agent tests go through `Load`, `Prepare` and `Configure` with a fake config home and `t.TempDir()`, reading the files written. Override policies (refused keys, keybinding values) are tested through `Load` on real override files, not through private functions.
- The 6 `TestAgentOverride*` tests in `cmd/kota/main_test.go` move into `internal/agent`.
- `main_test.go` keeps one test that `prepareSession` mounts every one of `Prepared.ReadOnly` and probes it read-only.
