# 01 — Move the Agents into internal/agent behind Load

Status: ready-for-agent
Category: refactor

## Parent

`.scratch/agent-module/PRD.md`

## What to build

A new package `internal/agent` that holds opencode and pi as unexported adapters, replacing `internal/opencode`, `internal/pi`, and main.go's `agentSetup` and `agentFor` (`cmd/kota/main.go:309-415`).

- `agent.Load(name, configHome) (*Agent, error)` picks the agent and reads its **Agent overrides**, replacing `loadOverrides` (`main.go:483`). It writes nothing. An unknown name keeps today's error.
- `Agent` exposes `Name()`, `Overrides()` (the host paths found, for the "agent override:" line), `FullAuto(auto)` and `Approval(auto)`.
- `FullAuto` moves the "pi has no permission system" fact out of `internal/approval`: `alwaysAuto` and `approval.FullAuto` are deleted, and `confirmFullAuto` takes the agent's answer as a bool. `Approval` is derived from `FullAuto`, so pi's line and its always-full-auto behaviour come from one fact.
- The in-sandbox paths (`opencodeConfigPath`, `opencodeConfigDir`, `opencodeInstructionsPath`, `piAgentDir`, `piSessionDir`, `main.go:63-77`) and pi's ticket_done fact move into the package.
- The override policies (`ConfigOverride`, `CLIOverride`, `SettingsOverride`, `KeybindingsOverride`) and the renderers become private.

For this issue main.go may still read the agent's config targets, render step, note path, extensions and env through unexported-field accessors or a temporary internal method; issue 02 replaces that wiring with `Prepare` and `Configure`. Keep that bridge as small as possible.

Prep has no agent: `session.agent` becomes a nil `*agent.Agent` instead of an empty `agentSetup{}`.
