## What to build

`startSession` (`cmd/kota/main.go:1334-1379`) and `cmdCheck` (`main.go:1618-1641`) each run the Sandbox probes and then the Engine VM probes (`check.Run`, `probe.Failed`, `printResults`, `sess.engine.Probes(ds, sess.engine.ProbeTargets(sess.gateway))`). They differ only in policy: `run` stops at the first failing suite and prints its failures; `check` runs both and prints every result.

```go
func check.Verify(ds *docker.Session, gw sandbox.Gateway, expect sandbox.Expect,
                  engine enginesession.State) (Results, error)
type Results struct{ Sandbox, Engine []probe.Result } // Engine nil when not run
```

- `Verify` runs the Sandbox probes, then the Engine VM probes when the Engine VM is on and got ready.
- `startSession` refuses when either suite has failures and prints the failures; `cmdCheck` prints every result with its timing, as today.
- check's `reportedEngine` adapter stays as it is.

Behaviour change: when a Sandbox probe fails, `run` and `shell` now also run the Engine VM probes before refusing, and list the failures of both. Only the refusing path changes.
